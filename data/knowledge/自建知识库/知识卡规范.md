# 梦卡自建现代简体中文知识卡规范

> 版本：0.1  
> 建立日期：2026-09-01  
> 当前阶段：仅完成知识库骨架；尚未撰写正式解梦正文，尚未向量化，模型调用次数为 0。

## 一、知识库定位

梦卡自建知识库不是一本“标准答案式解梦书”，而是一套有来源、可追溯、可持续审校的现代简体中文梦境叙事资料。

每张知识卡由三层构成：

1. **文化依据层**：记录公版古籍原典中与该梦象相关的历史材料，只说明古代文本如何记述，不直接继承吉凶、寿命、疾病或预言结论。
2. **现代研究层**：记录开放获取论文、专业机构科普或合法获得的研究资料，只支持梦、睡眠、记忆、压力和情绪等一般性边界，不把单一梦象固定对应为某种心理结论。
3. **梦卡原创层**：由梦卡撰写现代简体中文的温和叙事、自我觉察问题与行动建议。此层是面向用户的主要内容，并由梦卡拥有或取得完整使用权。

任何一层缺失都必须明确标记，不允许让大模型补造来源。

## 二、允许与禁止的来源

### 允许作为依据

- 已核明作者、版本、保护期和使用地域的公版原典；
- 明确允许相应用途的开放许可资料，例如符合条款的 CC BY、CC BY-SA 内容；
- 开放获取论文、政府或高校公开研究、专业机构公开科普；
- 梦卡团队原创稿件；
- 已签署书面委托或授权协议，且明确允许改写、切分、向量化、模型检索和用户展示的内容。

### 不得直接入库

- 购买、租阅或带 DRM 的商业电子书全文；
- 未取得许可的现代译本、白话文、注释、校订和出版社整理内容；
- 来源不明的网盘、论坛、公众号转载和聚合网站内容；
- 搜索结果摘要、模型记忆或模型自行生成的“原文依据”；
- 把古籍中的吉凶、疾病、寿命或灾祸判断直接改写成对现代用户的确定性结论；
- 仅通过替换近义词规避原文表达的仿写内容。

## 三、单张知识卡字段

每张卡使用一个独立的 Markdown 或结构化记录，必填字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `card_id` | string | 永久编号，例如 `DREAM-001`；发布后不复用 |
| `title` | string | 现代简体中文梦象名称 |
| `aliases` | string[] | 常见说法、近义表达、口语表达 |
| `category` | enum | 动作、场景、人物关系、物件自然、主题体验 |
| `retrieval_cues` | object | 场景、人物、物件、动作、情绪等检索线索 |
| `scope_note` | string | 该卡覆盖什么、不覆盖什么 |
| `cultural_context` | string | 梦卡原创的文化背景说明；没有合格依据时留空并标记 |
| `modern_context` | string | 与睡眠、记忆、情绪等有关的一般性边界说明 |
| `reflection_prompts` | string[] | 供用户自我觉察的问题，不替用户下结论 |
| `gentle_actions` | string[] | 低风险、可选的记录或反思建议 |
| `safety_note` | string | 非预言、非诊断及必要的求助提示 |
| `evidence` | object[] | 每项依据的完整记录，格式见下节 |
| `rights_status` | enum | 权利状态，格式见下节 |
| `author` | string | 原创撰写人或团队标识 |
| `reviewer` | string | 内容审校人；未审时填 `pending` |
| `version` | string | 语义版本，例如 `0.1.0` |
| `status` | enum | `outline`、`draft`、`reviewed`、`production_ready`、`retired` |
| `created_at` | date | 建立日期 |
| `updated_at` | date | 最后修订日期 |

## 四、依据记录格式

`evidence` 中每一项至少包含：

```yaml
- evidence_id: EVID-0001
  evidence_type: public_domain_primary | open_research | licensed_source | expert_review
  title: 资料名称
  author_or_org: 作者或机构
  edition_or_date: 版本或发布日期
  locator: 卷、章、页码、段落或稳定链接
  source_url: 来源链接
  source_file_sha256: 本地保存时填写
  permitted_use: 允许的使用方式
  rights_evidence: 公版判断、开放许可证或授权合同编号
  claim_supported: 该资料具体支持本卡中的哪一句边界说明
  quote_used: false
  verified_by: 核验人
  verified_at: 核验日期
```

`claim_supported` 必须具体。不能只写“参考某书”，也不能用一篇关于睡眠的论文去证明“蛇必然代表焦虑”。

## 五、权利与内容状态

### `rights_status`

- `original_pending_review`：梦卡原创草稿，权利链尚未复核；
- `evidence_verified`：引用依据和权利证据已核验；
- `commercial_approved`：允许进入生产知识库；
- `restricted_internal_only`：仅供内部研究，不得进入生产；
- `rejected`：来源、质量或权利不合格。

### 生产闸门

知识卡只有同时满足以下条件才能标记为 `production_ready`：

1. 正文为现代简体中文原创内容，并通过重复度检查；
2. 所有事实性或文化来源表述都有可追溯依据；
3. 每项依据的权利状态明确，未使用未经授权的现代译注或商业电子书；
4. 未包含确定性预言、吉凶断言、疾病诊断、寿命判断或治疗承诺；
5. 内容审校人与权利审核人完成记录；
6. `rights_status= commercial_approved`；
7. RAG 只能引用本卡已审核字段，不得用模型记忆补充“书中说法”。

## 六、写作规则

### 允许的表达

- “这类梦可能与近期的情绪体验同时出现。”
- “如果梦中的这一部分让你印象深刻，可以留意它带来的感受。”
- “传统材料中曾出现过相近意象；这里仅作为文化背景。”
- “梦境没有唯一、固定的解释。”

### 禁止的表达

- “梦见某物就代表你一定……”
- “这预示你近期会……”
- “这个梦说明你患有……”
- “根据某书，你必然……”（没有连续原文和已核验来源）
- 将模型生成内容包装成专家诊断、科学定论或古籍原文。

## 七、建议的机器可读结构

首版可同时保存 Markdown 人工稿和 JSONL 生产稿。进入检索时只索引以下字段：

- `title`
- `aliases`
- `retrieval_cues`
- `scope_note`
- `cultural_context`
- `modern_context`
- `reflection_prompts`
- `gentle_actions`

`rights_evidence`、合同信息、审校记录和内部备注不发送给模型，只用于入库闸门和审计。用户界面可以展示经过筛选的资料名称、作者/机构和来源链接。

## 八、第一轮样稿验收

在 50 条目录确认后，只选择 5 张卡撰写样稿。建议覆盖不同类型：

1. 被追赶（动作）
2. 迷路（动作/空间）
3. 水域（场景）
4. 牙齿脱落（身体体验）
5. 已故亲友（人物关系）

样稿验收重点是来源是否真的支撑表述、用户语言是否自然、是否会被误解为诊断或预言。样稿未通过前，不批量生成剩余正文，不建立生产索引。
