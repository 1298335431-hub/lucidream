## 登录修正

依据用户提供的《知乎 - 知乎0.pdf》（获取用户信息）及《知乎 - 知乎2.pdf》（OAuth 快速开始）：

- `GET https://openapi.zhihu.com/user` 使用 `Authorization: Bearer <用户 OAuth access_token>`
- 不再把开发者 Access Secret 当作 `/user` 的 Bearer，也不再要求登录配置包含该 Secret
- 账号绑定使用正式文档给出的顶层 `uid`，不使用昵称或头像作为账号标识
- 保留 int64 UID 原始数字文本，避免 JavaScript 精度损失误绑定账号
- 仅向应用返回昵称和可信 HTTPS 头像地址，不保留手机、邮箱、描述、授权码或令牌
- FastAPI 将最小资料按已验证账号保存，`/auth/me` 返回资料，原账号菜单展示昵称/头像
- 体验码账户与知乎账户不自动合并，历史与额度仍隔离
- 回调 state、一次性流程和有效期检查保留，缺失 state 不建立账号登录
- 用户后续确认完成回调登记，配置改为 `callbackRegistered=true`；该标志表示用户确认，不替代真实授权验收

## 个人账号分享待办

用户提供的《知乎 - 知乎就.pdf》只定义圈子发布：

- `POST https://openapi.zhihu.com/openapi/publish/pin`
- 社区用户 token 作为 `app_key`，配合独立 `app_secret` 做 HMAC 签名
- `title`、`content`、`image_urls`、`ring_id`；每小时最多 5 条
- 未定义使用 OAuth 用户授权令牌发布的方式，也未说明如何由 `uid` 获取该用户社区凭证
- 不得把 OAuth App Key、Access Secret、UID 或一个产品账号的社区凭证互相替换

需要知乎确认：是否提供授权用户本人发布想法/图文的 OAuth 接口或逐用户社区授权、所需 scope/权限、图片上传或可抓取图片 URL 要求、返回链接，以及失败重试/去重规则

当前梦卡图片接口需登录 Cookie，不能原样作为给知乎抓取的公开 image_urls；在明确个人发布能力后再设计经用户确认的短时图片访问或官方上传，不公开整份梦境库，不开通 TOS

分享页面保留文案编辑、梦卡预览、复制和下载，增加新窗口打开知乎首页的普通链接；不附带文案、图片或令牌，不自动提交，不显示“已发布”或伪造发布链接。提示用户确认知乎当前登录账号，手动粘贴文字、添加已下载图片
