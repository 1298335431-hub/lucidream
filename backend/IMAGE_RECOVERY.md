# 图片失败恢复

当前每个已确认梦境版本最多首次生成一次、补生成一次。`quality_retry_count`
同时限制自动质检补生成和用户点击的失败重试；刷新、重启、重新核验不重置次数。

- 其他形态主体明确不匹配：强化主体与角色绑定，自动补生成一次；第二次仍不匹配，展示保留图片和提示。
- 核验无法判断或服务不可用：保留图片，可重试核验原图，不自动消耗补生成机会。
- 文字/色块检查不通过：共用一次补生成机会，耗尽后终止。
- 供应商明确失败：允许用户手动补生成一次。
- 有任务编号但等待超时：查询原任务；禁止直接另开生图请求。
- 提交超时且无法获得任务编号：标记 `submission_unknown`，禁止自动和手动重复提交。
  维护人员按记录编号、时间及 `image_events` 核查供应商任务记录；不要直接清空状态后重跑。
- 最终失败：文章继续保留，页面提供返回文章及记录编号。

存储在配置的 `DREAMCARD_DATABASE_PATH` 数据库中：`image_generations` 记录当前状态、
`image_events` 记录错误及任务编号、`image_assets` 保存成功下载的候选图片二进制。
本地存储失败会记录服务端错误，不能承诺这张图片已持久保存。

账户额度页目前是演示数据，没有后端用户扣费/退款账本。本功能不扣用户额度，
也不声称已执行退款。供应商仍可能对实际提交的请求收费。
正式收费上线需要先实现用户归属、额度预留、成功结算和失败释放的幂等账本。

故障验证使用注入的模拟模型与临时数据库，不调用真实生图或视觉模型。
