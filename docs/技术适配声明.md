## 1. 产品形态判断

- 产品类型与核心任务：桌面 Web 端梦境记录、受控古籍检索、梦境解读与梦卡生成产品。
- 核心交互：分阶段确认。用户录入梦境后先确认梦象，最多回答一个澄清问题，再等待知识库检索、文字解读和梦境插图生成，最后预览并下载梦卡。
- 工作流性质：固定业务流程。页面跳转、人工确认、重试、超时、降级和停止条件由代码状态机控制；模型不自由规划流程。
- 开发路径：纵向切片。梦象确认、生成进度、来源展示、插图预览和卡片下载都需要用户亲自操作才能判断产品是否成立。
- 目标终端：第一阶段只做桌面浏览器 Web 端，同时保证最终下载的 1080 × 1920 PNG 适合手机保存与分享。
- 当前阶段范围：只完成第一条可验证纵向切片，即梦境文字输入、浏览器语音入口、梦象提取、人工修订与确认、本地会话恢复，以及基础错误和危机中断状态。
- 当前阶段不做：知识库/RAG、传统资料引用、正式解读、图片生成、卡片下载、登录、账户、云同步、跨设备梦境册、站内分享、年度统计、生产级多用户并发和正式数据迁移。

## 2. 采用的默认方案

| 方案 | 采用结论 | 原因 |
| --- | --- | --- |
| Python 3.11 | 采用 | 本机已有 `/Users/a7/.local/bin/python3.11`，符合新项目默认基线 |
| FastAPI | 采用 | 为模型、RAG、任务状态和生成资产提供可独立验证的后端 API |
| Pydantic | 采用 | 强校验梦象提取、检索结果、模型输出、任务状态和错误结构 |
| pytest | 采用 | 覆盖状态流转、解析器、错误路径、降级和恢复逻辑 |
| `/api/v1` | 采用 | 当前尚无既有后端契约，可直接使用默认版本前缀 |
| 固定代码状态机 | 采用 | 梦卡流程已经明确，不需要模型动态规划和自主选工具 |
| 官方 SDK 或已验证兼容接口 | 采用 | 阿里云模型调用统一放在后端模型适配层 |
| `.env` 与 `.env.example` | 采用 | API Key 仅由后端读取，真实秘密不进入前端、仓库或日志 |

| 异步任务与状态轮询 | 解读和图片生成整体可能接近 60 秒，页面刷新后仍需继续查看 | 暂缓，第一阶段仅有短时梦象提取请求 |
| 本地资产目录 | 保存模型生成的临时插图、降级图和测试产物 | 暂缓，第一阶段不生成文件资产 |

| SSE | 当前流程只需要阶段进度与最终结果，且必须支持刷新恢复 | 暂缓，优先使用持久化任务加轮询；若真实体验需要逐字输出再评估 |
| 外部任务队列 | 第一阶段单用户、低并发 | 暂缓；出现并发任务积压或单进程恢复不足时再引入 |
| 对象存储 | 第一阶段本地 MVP | 暂缓；正式部署和多用户阶段再评估 |

## 4. 模型与工作流适配

第一阶段实际只调用阿里云通义千问大模型 Qwen3.8-Flash。其余模型和审核服务是后续阶段的既定方向，不作为第一阶段已接入能力。

| 阶段 | 模型或服务 | 约束 |
| --- | --- | --- |
| 危机中断 | 本地受控关键词规则 | 第一阶段临时保护措施；云端内容安全审核待后续接入 |
| 梦象提取 | 阿里云通义千问大模型 Qwen3.8-Flash | 关闭思考模式，使用严格结构化输出 |
| 书库向量化 | 阿里云百炼 Text-Embedding-V4 | 已真实接入，512维；当前仅是未商用批准的开发候选索引 |
| 结果排序 | 阿里云通义千问 Qwen3-Rerank | 已真实接入并完成五组链路验收 |
| 解读生成 | 阿里云通义千问大模型 Qwen3.7-Plus | 已选定，暂缓 |
| 插图生成 | 阿里云通义万相大模型 Wan2.7-Image | 已选定，暂缓 |

第一阶段的标准成功路径只有一次模型调用：梦象提取。用户修订后由确定性代码持久化最新梦象与修订号。后续阶段再接入检索、排序、解读、审核、图片生成和卡片渲染。

模型名称、快照版本、API 地址、超时、重试和参数全部通过后端配置读取。生产环境固定经过测试的模型快照，不依赖会自动变化的最新版别名。

## 5. 偏离或暂缓的默认方案

| 默认方案或既有情况 | 适配结论 | 原因与影响 | 重新评估条件 |
| --- | --- | --- | --- |
| 手册默认 Next.js 前端 | 保留现有 React 19、Vite 8、TypeScript 5.7、Tailwind CSS 4 | 当前项目构建成功，迁移到 Next.js 不会改善核心模型链路，反而增加无关改动 | 需要服务端渲染、复杂路由或 Next.js 平台能力时 |
| 手册默认 Node 22 LTS | 项目 `.mise.toml` 已固定 Node 22；当前 shell 为 Node 24 | 当前 Node 24 构建通过，但正式开发和 CI 应使用 `.mise.toml` 的 Node 22 保证一致 | 升级前完成依赖兼容和构建回归 |
| 后端先行 | 改为纵向切片 | 梦象确认、进度、来源和卡片预览属于 Agent 质量的一部分 | 不回退；后续仍保持后端能力可独立验证 |
| Agent Blueprint 的通用 Agent Loop | 第一阶段不采用开放式 Agent Loop | 梦卡有固定八步流程，代码工作流比模型自由调度更可控 | 产品出现动态选工具或开放式多轮任务时 |
| Agent Blueprint s16 Workflow Runtime | 采用其“脚本决定编排、任务可恢复”的原则，由梦卡专用工作流服务实现 | 避免复制整套通用运行时，同时保持固定步骤、状态和恢复能力 | 工作流数量增加或需要跨工作流复用时再抽象 |
| PRD 中“静态前端托管与未来 API 服务” | 当前阶段即新增后端 API | 已确认的模型、知识库、安全审核和密钥保护无法安全放在纯前端 | 不回退 |
| 现有落地页中的登录、定价、永久加密存储、自由风格和作品图库 | 不作为当前产品事实，第一阶段移除或改写 | 这些内容与已确认 PRD 不一致，部分还作出了未经实现的承诺 | PRD 明确新增并完成相应后端能力后 |

- 正常/空白/超长梦境输入、梦象结构和澄清次数校验

### 真实模型冒烟

- 使用一条非个人测试梦境调用 Qwen3.8-Flash。
- 验证“真实模型 → SQLite 保存 → 梦象确认 → 会话恢复读取”完整路径。
- 记录模型名称、调用成功状态和修订号；测试记录在验证后删除。
- 后续模型契约、60 秒生成目标、下载成功率和修订率，随第二阶段相应能力实现后再验收。
